# 第 1 章　项目来源、基线与统计口径

## 1.1 项目来源

本作业的分析对象是 **MiCode/Notes**，即小米便签的社区开源版本。该项目由 MIUI 团队发起，托管在 GitHub 的 MiCode 社区仓库下（`MiCode/Notes`），使用 Java 语言开发，面向 Android 平台。项目遵循 Apache License 2.0 开源协议，并声明由 MiCode 社区维护。

本项目实现了一款功能完整的便签应用，核心能力包括：便签的创建、编辑、删除与文件夹分类管理，文本便签的清单模式，通话记录自动生成便签，桌面小部件的便签展示，以及便签与 Google Tasks 的同步。

## 附：数据契约表

data 包通过 `NotesProvider` 对外暴露数据，以下是全部可访问的 URI 及其说明。

| URI 路径 | MIME 类型 | 对应表/字段 | Provider 路由说明 |
|---|---|---|---|
| `content://micode_notes/note` | 无（集合） | `note` 表 | `URI_NOTE`：查询/插入/更新/删除全部便签与文件夹 |
| `content://micode_notes/note/#` | 无（单条） | `note` 表，`#` 为 `_id` | `URI_NOTE_ITEM`：按 id 操作单条便签；删除时 id≤0 的系统文件夹受保护 |
| `content://micode_notes/data` | 无（集合） | `data` 表 | `URI_DATA`：查询/插入/更新/删除便签正文数据 |
| `content://micode_notes/data/#` | 无（单条） | `data` 表，`#` 为 `_id` | `URI_DATA_ITEM`：按 id 操作单条正文数据 |
| `content://micode_notes/search` | 无 | `note` 表（摘要模糊匹配） | `URI_SEARCH`：从 `pattern` 参数取关键词，按 snippet 模糊搜索便签 |
| `content://micode_notes/search_suggest_query/*` | 无 | `note` 表 | `URI_SEARCH_SUGGEST`：系统搜索建议，关键词从路径段取 |
| `content://micode_notes/text_note` | `vnd.android.cursor.dir/text_note` | `data` 表 | 文本便签类型的常量 URI，见 `Notes.TextNote.CONTENT_URI` |
| `content://micode_notes/call_note` | `vnd.android.cursor.dir/call_note` | `data` 表 | 通话记录便签类型的常量 URI，见 `Notes.CallNote.CONTENT_URI` |

**关键字段**（`Notes.NoteColumns` / `Notes.DataColumns`）：`note` 表以 `_id` 为主键，通过 `parent_id` 组织文件夹层级，`type` 区分便签/文件夹/系统文件夹，`version` 用于同步版本控制；`data` 表以 `note_id` 关联到 `note` 表，`mime_type` 区分文本便签与通话记录，`data1`～`data5` 为含义随类型变化的通用字段。

### 耦合关系说明

`Notes` 数据契约是全局数据访问的公共基础，被工程内 **5 个包** 引用：

- **model（2 处）**：`Note.java`、`WorkingNote.java` —— 通过契约常量读写便签数据；
- **tool（2 处）**：`DataUtils.java`、`BackupUtils.java` —— 数据工具与备份恢复；
- **widget（3 处）**：`NoteWidgetProvider.java`、`NoteWidgetProvider_2x.java`、`NoteWidgetProvider_4x.java` —— 桌面小部件读取便签内容；
- **gtask（5 处）**：`SqlData.java`、`SqlNote.java`、`Task.java`、`TaskList.java`、`GTaskManager.java` —— 同步时读写本地数据；
- **ui（9 处）**：列表、编辑、提醒、设置等界面直接通过契约操作数据。

由此形成的耦合特征：

1. **ui ↔ gtask.remote** 存在双向耦合：ui 触发同步、gtask.remote 同步完成后又通过 ContentProvider 通知 ui 刷新（待核实具体调用链）；
2. **ui ↔ widget** 存在双向耦合：ui 编辑便签后通知 widget 刷新，widget 点击又跳转回 ui 的编辑页（待核实具体调用链）。

以上耦合关系以源码 import 与调用关系为准，标注"待核实"的部分将在第 2 章结合流程图进一步确认。
